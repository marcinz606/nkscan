# Nikon LS-50 ED (Super Coolscan V ED): nkscan backend

The scanner's job here is to capture the highest-quality 16-bit linear raw off the
CCD. Inversion and colour are left to downstream tools like NegPy.

## What's implemented

| Area | Detail (wire facts) |
|---|---|
| USB transport | `src/scsi/usb.rs`. Nikon's non-Mass-Storage SCSI over two bulk endpoints (`CDB → 0xD0 phase → data → 0x06 sense`), with an 8-byte compact-sense parse. Uses `nusb`'s blocking API, no async runtime. |
| Init / arming | SANE `coolscan3` sequence: RESERVE, EVPD adapter probe, MODE SELECT page 0x03 (base res `0x0FA0` = 4000 dpi), self-test plus lamp warm-up (non-feeder holders only), cold-start unit-attention drain. |
| 16-bit linear raw | SET WINDOW `d[26]=0x0E` gives 14-bit values right-justified in a big-endian `u16` (0 to 16383), 2 bytes per sample, planar RGB(I). The gamma LUT is the identity, so the output stays linear (raw for downstream inversion). |
| Infrared (RGBI) | `--ir` adds the IR plane (channel `0x09`) as a 4th planar channel, written beside each frame as `*_ir.tiff`. It is the dust and scratch mask. |
| Single frame | `scan` / `scan_at(offset)`: prepare, arm, SCAN, drain, then decode. |
| Strip batch | `scan_strip`: SET BOUNDARY declares the whole strip so the feed advances, then each frame is selected by window Y-offset (`frame·pitch + offset`). `FRAME_PITCH_MM = 38.0` plus `--offset` handles residual mechanical drift. |
| Geometry autodetect | Adapter geometry and sensed frame count read live from INQUIRY EVPD page 0xc1 (`base_res`, `native_x/y`, `n_frames`). Self-calibrates per adapter, and falls back to SA-21 constants when the page is absent. |
| Autofocus | `--af`: firmware autofocus at the frame centre (`E0 0xA0` + focusX/Y, then `E1 0xC1` read-back). About 5× sharper, and it fixes the focus-parked-at-0 softness. Re-focuses per frame. This payload does not eject. |
| Autoexposure | `--ae`: AE pre-pass (`d[42]=0x20` + GET WINDOW read-back), baked into the real scan. It is marginal in practice: the firmware only re-measures on a cold or idle calibration event, otherwise it hands back the seed. The code detects that case and falls back to fixed exposure. Off by default. |
| Eject | `eject`, or the automatic eject after a strip: VENDOR `E0 0xD0`. |
| DPI grid | The LS-50 scans only at `base_res / pitch`, so `--dpi` snaps to the grid (300 becomes an effective 307, for example). |

A few things are not supported. `--samples > 1` arms a multi-pass scan that never
streams, so the parser rejects it. INQUIRY does not report the frame pitch, so it stays
hardcoded at `38.0 mm` with `--offset` for correction. The macOS and Windows native-SCSI
transports are stubbed; the USB path is cross-platform through `nusb`.

## Tested on live hardware

Verified against a physical LS-50 with the SA-21 feeder (2026-07):

- Read-only verbs, confirmed live from this branch's CLI: `status` returned `NoFilm`, and
  `info` returned `Nikon LS-50 ED rev 1.02`, holder `Feeder`, caps
  `{ n_frames, base_res 4000, native_x 3945, native_y 5958 }`.
- Capture, verified across the branch: 16-bit linear-raw single frames, plus a 6-frame
  RGBI strip at 4000 dpi with `--ae --af --ir` followed by an eject. Autofocus moved focus
  from 0 to about 228 and the result was visibly sharper. A bare strip scan auto-detected
  6 frames from page 0xc1.

Everything is clean under `cargo fmt` and `clippy -D warnings`, and 115 unit tests pass
without hardware. They cover geometry snapping, page-0xc1 parsing, holder and status
classification, TIFF path naming, CLI arg wiring, and the flag-to-settings mapping.

## CLI: running actions

Build with `cargo build --release`; the binary is `target/release/nkscan` (or use
`cargo run -- …`).

```
nkscan [--device ls50] [--path /dev/sgN] [-v|-vv|-vvv] <COMMAND>
```

The global options: `--device` selects the scanner (default `ls50`); `--path` is the SCSI
node for SCSI-only devices (unused by USB); `-v/-vv/-vvv` raise the log level to
info/debug/trace (the default is a quiet `warn`, and `RUST_LOG` overrides it).

| Command | What it does | Example |
|---|---|---|
| `status` | Print readiness (`Ready`/`NoFilm`/…). Read-only. | `nkscan status` |
| `info` | Inquiry identity, holder, and adapter caps. Read-only. | `nkscan info` |
| `watch` | Poll and print every state change (Ctrl-C to stop). | `nkscan watch` |
| `scan` | Scan one frame to a TIFF. | `nkscan scan out.tiff --dpi 4000 --af` |
| `strip` | Scan a strip to `OUT_00.tiff`, `OUT_01.tiff`, … then eject. | `nkscan strip roll.tiff --dpi 4000 --ir --af` |
| `eject` | Eject the loaded film and exit. | `nkscan eject` |

The scan flags, shared by `scan` and `strip`: `--ir` (infrared plane), `--dpi N` (default
300, grid-snapped), `--ae` (autoexposure pre-pass), `--af` (firmware autofocus), and
`--offset MM` (feed-axis nudge for pitch drift). The strip-only flags: `-n/--count N`
(frame count; omit it to auto-detect from the adapter) and `--no-eject` (keep the strip
loaded after the batch).

```bash
# quick preview of a single frame
nkscan scan preview.tiff

# full 6-frame strip: 4000 dpi, IR + autofocus, auto-detect count, then eject
nkscan strip roll.tiff --dpi 4000 --ir --af

# force 4 frames, keep loaded, nudge the feed 0.5 mm, verbose SCSI logging
nkscan strip roll.tiff -n 4 --no-eject --offset 0.5 -vv
```

## Why `main.rs` is thin, with a `cli/` module

`src/main.rs` is four lines: `mod cli;` and a `main` that runs `cli::run()`, prints any
error, and sets exit code 1. All CLI logic lives under `src/cli/`, so it stays out of the
public library. `src/lib.rs` exposes only the scanner and SCSI layers, which means a GUI or
another front-end can link the same lib without inheriting the CLI types.

- `cli/mod.rs` holds the `clap` types (`Cli`, `Commands`, `ScanCommon`) and `run()`, which
  parses args, inits tracing, opens the device, and dispatches. The handlers call `Backend`
  methods and never name a concrete device.
- `cli/device.rs` is the one place any per-device `match` lives.
- `cli/output.rs` does the TIFF writing, device-neutral.

Errors bubble up as `Box<dyn std::error::Error>`. Every driver error (`ScanError`,
`scsi::Error`, `image`, `io`) already implements `Error`, so `?` just works and `main`
prints it. There is no bespoke error enum, and no `.unwrap()` or panics on expected
failures like a missing device or no film.

### The device seam (generic, minimal)

Adding another Coolscan later should not mean rewriting the CLI. The seam is deliberately an
enum with a `match`, not a trait:

```rust
enum Device  { Ls50 /*, Ls9000 */ }              // clap ValueEnum
enum Backend { Ls50(Ls50<UsbTransport>) /*, Ls9k(Ls9k<SgDevice>) */ }
```
